## 1. Row-by-Row On-Device Evidence

### 1.1 CVE-2026-21385 — KGSL align sign-extension → "userland cannot control align" ✅ TRUE

- `test_gpumem` (GPUMEM_ALLOC, align 0–255): **all `errno=95 (ENOTSUP)`** → GPUMEM_ALLOC functionality disabled.
- `test_align` (GPUOBJ_ALLOC, align 0–26): **all `errno=22 (EINVAL)`** → GPUOBJ_ALLOC not registered.
- `test_import` (GPUOBJ_IMPORT, align 0–255): all succeeded, but combined with the reverse-engineering analysis (`REVERSE_ANALYSIS_1.22_009.md` §9.3: import forcibly overwrites align based on size) → the userland value has no effect.
- **Conclusion**: the three ioctl paths that could inject align = ENOTSUP / EINVAL / forced overwrite → userland cannot control the align that reaches `kgsl_iommu_get_gpuaddr`. ✅

### 1.2 CVE-2026-KGSL-UAF — KGSL syncsource → "SYNCSOURCE ioctl returns ENOTTY" ✅ TRUE

- `test_sync_errno`: `CREATE: r=-1 errno=25(Inappropriate ioctl for device)` → **ENOTTY**.
- `kgsl_syncuaf_probe`: `iterations=200000, fence succ=0, errors=200000, No crash`.
- **Conclusion**: SYNCSOURCE_CREATE/FENCE not registered (ENOTTY), unreachable. ✅

### 1.3 CVE-2024-36971 — Routing table (dst) UAF → "loopback DST never becomes obsolete" ✅ TRUE (environmental)

- `ip route` and `ip -6 route`: **both empty** (no routing table entries at all).
- Interfaces: only `lo` (127.0.0.1/8) is UP and has an inet address; `wlan0` is NO-CARRIER/DOWN; `dummy0` is NOARP (link-local v6 only); no external network.
- `cve_2024_36971_poc`: repeatedly outputs `connect: Network is unreachable` (cannot establish a socket connection; the conditions that trigger `__dst_negative_advice()` do not exist).
- **Conclusion**: no routes + no ICMP trigger surface → the UAF cannot be triggered in this environment. ✅

### 1.4 CVE-2024-0582 — io_uring PBUF_RING UAF → "the PBUF_RING feature does not exist (requires 5.19+)" ✅ TRUE

- `cve_2024_0582_mmap_uaf`: `io_uring fd=3, features=0x7ff`; `REGISTER_PBUF_RING (opcode=22) failed: Invalid argument (errno=22)`.
  - `features=0x7ff` = bits 0–10 all set, **bit11 (`IORING_FEAT_PBUF_RING`=0x800) not set** → the feature flag does not exist.
- `cve_2024_0582_uaf_check`: `PROVIDE_BUFFERS → res=-22`, `REMOVE_BUFFERS → res=-22`.
- **Conclusion**: io_uring itself exists (`CONFIG_IO_URING=y`), but PBUF_RING (introduced in 5.19, commit `c7fb19428d67`) does not exist in 5.10.209. ✅

### 1.5 CVE-2024-38401 — KGSL UAF → "patched" ✅ TRUE

- `security_patch = 2024-07-05` → covers the 2024-06 Qualcomm/Android patches.
- syncsource (this CVE's trigger surface) returns ENOTTY on this device (see 1.2); the attack surface is likewise unreachable.
- **Conclusion**: both the patch timing and the closed trigger surface hold. ✅

### 1.6 CVE-2025-21479 / 21480 — KGSL UAF → "context creation is blocked" ✅ TRUE

- `gpu_context_bypass_dyn`: **all 31 context flag combinations (GL/VK/CL/…/zero flags) return `errno=22 (EINVAL)`**, `Total: 0/31 successful`.
  - `GPU_COMMAND (ctx=0/-1)` → `errno=19 (ENODEV)`; `GPUOBJ Alloc` → `Invalid argument`.
- **kernel dmesg**: `kgsl kgsl-3d0: legacy context switch not supported` (produced by this session's trigger).
- Module symbols: `msm_kgsl.ko` contains `a6xx_hwsched_*` (hardware scheduler mode).
- **Conclusion**: context creation is completely blocked; the micronode/command-submission path is unreachable. ✅

### 1.7 CVE-2024-43047 / 49848 — FastRPC UAF → "the fd must be obtained via HWBinder; shell has no permission" ✅ TRUE

- Node permissions: `/dev/adsprpc-smd` = `crw-rw-r-- 1 system system` (0664); `/dev/adsprpc-smd-secure` = `crw-r--r--` (0644).
- `test_adsp`: `open O_RDWR failed: Permission denied`; `open O_RDONLY ok`.
- `id`: shell is not in the `system` group.
- **Conclusion**: shell cannot directly obtain a writable fd (triggering the UAF requires O_RDWR); it would need `IDspService` over HWBinder (shell has no permission). ✅

### 1.8 CVE-2023-2163 — BPF verifier → "patched" ✅ TRUE

- `cve_2023_2163_probe`: `unprivileged_bpf_disabled=0` (BPF is available), but PROBE 1–7 all report `[OK] Patched: Verifier rejected`; `PROBE 6 (CVE-2023-2163 Exact Pattern) → rejected by verifier`.
- **Conclusion**: the verifier is patched (backported in 5.10.179+). ✅

### 1.9 CVE-2022-0847 — Dirty Pipe → "patched" ✅ TRUE

- `dirtypipe_test_dyn`: against a read-only file (`-r--r--r--`), `splice succeeded` + `write succeeded (4 bytes)`, but **the file content did not change** (both before and after are `AAAAAAAAAAAAAAAA`; offset 4 was not overwritten with `XXXX`).
- Version: 5.10.209 > the fixed release 5.10.102.
- **Conclusion**: the Dirty Pipe primitive does not hold → patched. ✅

### 1.10 CVE-2019-2215 — Binder UAF → "patched" ✅ TRUE

- `security_patch = 2024-07-05` is far later than the 2019-12 patch.
- **Conclusion**: patched. ✅

### 1.11 CVE-2021-22555 — Netfilter x_tables → "requires CAP_NET_ADMIN" ✅ TRUE (and stronger)

- `CapEff = 0` (no effective capabilities at all, including CAP_NET_ADMIN); `CapBnd = 0xc0` (no CAP_NET_ADMIN).
- On-device config: `CONFIG_NETFILTER_XTABLES=y` (x_tables is present) but **`CONFIG_USER_NS is not set`** and **`CONFIG_SYSVIPC is not set`** (which cuts off user-ns privilege escalation and msg_msg spray).
- **Conclusion**: triggering requires CAP_NET_ADMIN (setsockopt `IPT_SO_SET_REPLACE`), which the current shell cannot obtain. ✅

### 1.12 CVE-2024-56720 — BPF sockmap UAF → "CONFIG_BPF_STREAM_PARSER is not enabled" ✅ TRUE

- On-device `/proc/config.gz`: `# CONFIG_BPF_STREAM_PARSER is not set`.
- **Conclusion**: the sockmap prerequisite feature is not compiled in. ✅

### 1.13 CVE-2024-1086 / 26581 — nf_tables UAF → "CONFIG_NF_TABLES is not enabled" ✅ TRUE

- On-device `/proc/config.gz`: `# CONFIG_NF_TABLES is not set` (`CONFIG_NETFILTER=y` and `CONFIG_NETFILTER_XTABLES=y` are still enabled).
- **Conclusion**: nf_tables is not compiled into the kernel. ✅

### 1.14 CVE-2025-21655 — io_uring eventfd UAF → "only affects 6.1+" ✅ TRUE

- Kernel `5.10.209` < 6.1 (the `io_eventfd_signal()` flaw only exists from 6.1 onward).
- **Conclusion**: this version is outside the affected range. ✅

### 1.15 KGSL Cross-FD Access — GPU memory isolation bypass → "information disclosure / memory corruption, but no direct path to the kernel slab" ✅ TRUE

- `kgsl_mmap_probe_dyn`: **cross-FD mmap succeeded** — FD2 read the test pattern `data=0xcafebabedeadbeef` from FD1's buffer (information disclosure confirmed); larger buffers return EINVAL across FDs (limited).
- dmesg: `arm-smmu 3da0000.kgsl-smmu`, `kgsl-iommu gfx3d_user / gfx3d_secure Adding to iommu group` → GPU memory sits behind the IOMMU/SMMU, a different allocation path from the kernel slab (kmalloc).
- **Conclusion**: the cross-FD leak/corruption is real, but there is no direct path to the kernel slab. ✅
