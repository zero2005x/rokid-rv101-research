### 5.1.1 Dedicated "0x58 micronode" probes (v1 matrix ＋ v2 semantic verification)

> **Tools**: `deploy/kgsl_micronode_probe.c` (v1, nr×size matrix), `deploy/kgsl_micronode_probe2.c` (v2, semantic verification);
> cross-compiled with zig by `deploy/build_probe_zig.sh` (aarch64-linux-musl static).
> Raw output: `reports/kgsl_micronode_retest_2026-09-13.txt`.

| Tested | Result | Interpretation |
|------|------|------|
| `nr=0x58` × size `0x18/0x20/0x28/0x30` | **all `ret=0` (OK)** | size is **not validated** → this cannot establish which structure it is |
| `nr=0x58` arg=**NULL** | **EFAULT(14)** | it really is a **registered** ioctl (it does copy_from_user) |
| `nr=0x58` gpuaddr=`0xdead0000` / `0x4000000000` / all `0xffff` | **all `ret=0`** | it **does not validate the contents** → **the historical report's "IOCTL 0x58 ✅ returns data" is a false positive** and cannot be used as evidence that micronode is reachable |
| `GPU_COMMAND` nr `0x3d` / `0x40` / `0x4a` | `0x3d`, `0x4a` = **EINVAL**; **`0x40` = OK** | **the correct nr is `0x40` (`0xc0580940`)**; the other spellings used in the project are not this device's ioctl |
| `GPU_COMMAND 0x40` empty batch / fake cmdlist (`0xdead0000`, len=1) | both **OK** | likewise it **does not validate the cmdlist** → "OK" says nothing about the nature; the older report's "GPU command blocked／EOPNOTSUPP" does not hold, but this also cannot be treated as usable |
| `GPUMEM_ALLOC` nr `0x2f` (size=0x1000) | **EINVAL** | `0x2f` is **not** this device's allocation ioctl |
| `GPUMEM_ALLOC` nr `0x20` (size=0x1000, 8 flags) | **EOPNOTSUPP(95)** | this device's allocation path is nr `0x20` and the **feature is disabled** |
| `SYNCSOURCE_CREATE 0x30` / `CREATE_FENCE 0x32` | **ENOTTY(25)** / **ENODEV(19)** | the family is disabled (the latter means "device does not exist" rather than "no such ioctl") |
| `GPUOBJ_SET_INFO 0x3a` / `GPUOBJ_SYNC 0x56` | OK | the numbers exist (contents are still not validated) |
| `GPUOBJ_INFO 0x39` / `SPARSE_BIND 0x57` / `TIMESTAMP_EVENT 0x33` | ENODEV / EINVAL / EINVAL | correct parameters are needed before any conclusion |

**Conclusion (adjudicating the historical dispute)**

1. **Neither "0x58 works" nor "0x58 EOPNOTSUPP" holds**: this ioctl returns success for any content,
   so **any conclusion that uses it as evidence is invalid**; determining whether micronode is reachable requires a
   probe **whose return value changes with the parameters** (for example a full chain with a valid context/GPU object).
2. **The correct number for GPU_COMMAND is `0x40`** (`0x3D`／`0x4A` are EINVAL) → of the three spellings used in the project, only one works.
3. **GPU memory allocation is disabled in this generation** (nr `0x20` → EOPNOTSUPP): any older chain that needs
   GPUMEM_ALLOC is not feasible on this device; the "✅" for `0xc018092f` can only have come from an earlier generation or a different ioctl.
4. **`ret==0` alone cannot be used as evidence**: several ioctls in this driver do not validate their contents (0x58 and 0x40 are proven),
   so when citing older reports one must require a control showing that "changing the parameters changes the return value".
