## 2. Row-by-row verification

### 2.1 CVE-2026-21385 — KGSL align sign-extension → "userland cannot control align" ✅ true

- **Vulnerability existence** (`REVERSE_ANALYSIS_1.22_009.md` §9, grade B): disassembly of `kgsl_iommu_get_gpuaddr` (0xa6170) shows `ubfx x11,x8,#0x10,#0x10; lsl w11,w12,w11` as an inline `1 << align`, **with no capping and no `bl kgsl_get_align`** → the iommu path is in the pre-patch state (corresponding to CodeLinaro commit `91a0db3aa438...`).
- **Non-exploitability** (§9.3 measured table): although `GPUOBJ_IMPORT` can set align 0-255, `kgsl_ioctl_gpuobj_import` **forcibly overwrites align** based on size (≥1MB→20, ≥64K→16); `GPUOBJ_ALLOC` is not registered (EINVAL); `GPUMEM_ALLOC` returns ENOTSUP; `SPARSE_BIND` has no align injection.
- **Verdict**: the table's stated reason, "userland cannot control align (the ioctl is closed off)", agrees with the evidence. ✅

### 2.2 CVE-2026-KGSL-UAF — KGSL syncsource → "SYNCSOURCE ioctl returns ENOTTY" ✅ true

- **Symbols exist but are not registered** (grade A): `msm_kgsl.ko` contains the symbols `kgsl_ioctl_syncsource_create` and `kgsl_ioctl_syncsource_create_fence`, but they are not registered in the dispatch table.
- **Measured return values** (`REVERSE_ANALYSIS_1.22_009.md` §9.1, grade B): `0xc0300930`(SYNCSOURCE_CREATE) → **ENOTTY(25)**; `0xc0180932`(SYNCSOURCE_CREATE_FENCE) → **ENOTTY(25)**.
- **Verdict**: ✅ true.

### 2.3 CVE-2024-36971 — routing table (dst) UAF → "v1-v13, loopback DST never becomes obsolete" ✅ true (environmental)

- **Version unpatched** (`CVE-2024-36971_analysis.md`, grade B + public grade C): affects 5.5–5.10.218, fixed in 5.10.219; this device is 5.10.209 < 5.10.219, security patch 2024-07-05 < 2024-08-05 → **theoretically unpatched**.
- **Not triggerable** (`FINAL_STATUS_20260202.md` table + `CVE-2024-36971_analysis.md` §PoC test results): the multi-strategy v1–v13 PoCs (BPF spray of 16,384 192-byte objects succeeded) could not produce a UAF even over long runs; the device has no external network and cannot generate the ICMP unreachable that triggers `__dst_negative_advice()`; loopback DST does not become obsolete.
- **Verdict**: ✅ true, but this is "not triggerable in this environment", not "patched" (the table title "Verified but Not Exploitable" is correctly worded). The retained files `cve_2024_36971_v13.c`, `cve_2024_36971_bpf_spray.c`, `cve_2024_36971_cross_cache.c`, `cve_2024_36971_wifi.c` corroborate the multiple attempts.

### 2.4 CVE-2024-0582 — io_uring PBUF_RING UAF → "PBUF_RING feature does not exist (requires 5.19+)" ✅ true

- **Feature introduction version** (grade C): io_uring "ring-mapped supplied buffers" (`IORING_REGISTER_PBUF_RING`) was introduced by commit `c7fb19428d67` (`io_uring: add support for ring mapped supplied buffers`, `for-5.19/io_uring` branch) → **present only from 5.19 onward**.
- **This device**: 5.10.209 < 5.19 → the PBUF_RING opcode/feature does not exist. `CONFIG_IO_URING=y` (io_uring itself is present), but it **does not include** the PBUF_RING feature.
- **⚠️ Internal inconsistency note**: `CVE_PROBE_REPORT_20260203.md` §2 says "CVE-2024-0582 | CONFIG_IO_URING is not set", which **contradicts** the actual config (`CONFIG_IO_URING=y`); `FINAL_STATUS`/`NEW_CVE_ANALYSIS` and this extraction all show `=y`. **The §5.2 table's verdict (PBUF_RING does not exist) is the correct statement**; that row of the probe report is a typo.
- **Verdict**: ✅ true (the reason holds).

### 2.5 CVE-2024-38401 — KGSL UAF → "patched" ✅ true (with basis)

- **Patch timing** (grade C): Qualcomm KGSL syncsource UAF, patched in the June 2024 Android/Qualcomm security bulletins; this device's patch level 2024-07-05 → covered.
- **Measured** (`CVE-2024-38401_Test_Report.md`, grade B): v3–v6 (BPF spray 50k–100k iterations, multi-threaded race) **no crash**; double-destroy correctly returns EINVAL (`CVE-2025-21479_Analysis_Report.md` §vector B).
- **Verdict**: ✅ true. Strictly speaking, "patched" is supported jointly by the patch timing and the absence of a trigger (not by disassembly confirmation alone).

### 2.6 CVE-2025-21479 / 21480 — KGSL UAF → "context creation is blocked" ✅ true

- **Mechanism** (`CVE-2025-21479_Analysis_Report.md`, grade B): Adreno 621 uses A6XX GMU + **hwsched**; `kgsl kgsl-3d0: legacy context switch not supported`; all 31 context flag combinations return EINVAL.
- **Independent corroboration** (grade A): `msm_kgsl.ko` contains a large number of `a6xx_hwsched_*` symbols (`a6xx_hwsched_boot`, `a6xx_hwsched_context_detach`, `a6xx_hwsched_hfi_*`, …), confirming the hwsched hardware-scheduler mode.
- **Verdict**: ✅ true.

### 2.7 CVE-2024-43047 / 49848 — FastRPC UAF (ITW, NoviSpy) → "requires obtaining an fd via HWBinder; shell has no permission" ✅ true

- **Driver exists** (grade A): `CONFIG_MSM_ADSPRPC=m` (`/dev/adsprpc-smd`).
- **Permission surface** (`NEW_CVE_ANALYSIS_20260202.md` §4 + `CVE_PROBE_REPORT_20260203.md` §2, grade B): the node is `crw-rw-r-- (664) system:system`; shell (uid=2000) groups do not include `system`, so a direct open fails; only some ioctls work with O_RDONLY, while O_RDWR requires permission.
- **Trigger prerequisite**: an fd must be obtained through `vendor.qti.hardware.dsp@1.0::IDspService` (dspservice, hwbinder); shell has no permission for this HAL interface.
- **Verdict**: ✅ true.

### 2.8 CVE-2023-2163 — BPF verifier → "patched" ✅ true

- **Patch** (`CVE-2023-2163_BPF_Verifier_分析.md` §6, grade B + grade C): fix commit `71b547f56124`, backported into **5.10.179+**; this device is 5.10.209 → covered.
- **Verdict**: ✅ true.

### 2.9 CVE-2022-0847 — Dirty Pipe → "patched" ✅ true

- **Patch boundary** (grade C): Dirty Pipe was fixed in 5.10.102 / 5.16.11; this device is **5.10.209 > 5.10.102** → patched.
- **Measured** (`FINAL_STATUS_20260202.md` + `dirtypipe_test.c`, grade B): cannot overwrite read-only files.
- **Verdict**: ✅ true.

### 2.10 CVE-2019-2215 — Binder UAF → "patched" ✅ true

- **Patch timing** (grade C): patched in the 2019-12 Android security bulletin; this device's patch level 2024-07-05 → covered long before that.
- **Verdict**: ✅ true.

### 2.11 CVE-2021-22555 — Netfilter x_tables → "requires CAP_NET_ADMIN" ✅ true (and stronger)

- **Trigger path** (grade C): Google's official writeup "Turning \x00\x00 into 10000$" — the exploit requires `setsockopt(IPT_SO_SET_REPLACE)`, which needs **CAP_NET_ADMIN** (or must be obtained via a user namespace).
- **Blocked on this device** (grade A): `CONFIG_NETFILTER_XTABLES=y` (x_tables exists), but **`CONFIG_USER_NS is not set`** and **`CONFIG_SYSVIPC is not set`** (cutting off both the user-ns route to CAP and the msg_msg spray); shell has no CAP_NET_ADMIN.
- **Verdict**: ✅ true; "requires CAP_NET_ADMIN" is the most direct reason, and there is the additional blockage of user-ns/sysvipc being disabled.

### 2.12 CVE-2024-56720 — BPF sockmap UAF → "CONFIG_BPF_STREAM_PARSER is not enabled" ✅ true (grade A)

- **Direct config evidence**: `# CONFIG_BPF_STREAM_PARSER is not set` (obtained by decompressing the IKCFG embedded in the kernel).
- **Verdict**: ✅ true.

### 2.13 CVE-2024-1086 / 26581 — nf_tables UAF → "CONFIG_NF_TABLES is not enabled" ✅ true (grade A)

- **Direct config evidence**: `# CONFIG_NF_TABLES is not set` (`CONFIG_NETFILTER=y` and `CONFIG_NETFILTER_XTABLES=y` are still on, but nf_tables is not compiled).
- **Verdict**: ✅ true.

### 2.14 CVE-2025-21655 — io_uring eventfd UAF → "affects 6.1+ only" ✅ true

- **Affected versions** (grade C): the RCU-delay flaw in `io_eventfd_signal()`, whose fix commit was backported at the earliest to the **6.1.y** stable branch → affected only from 6.1 onward; this device's **5.10.209** is out of scope.
- **Verdict**: ✅ true.

### 2.15 KGSL Cross-FD access — GPU memory isolation bypass → "information disclosure/memory corruption, but cannot reach the kernel slab directly" ✅ true

- **Cross-FD holds** (`CVE_2025_21479_EXPLOIT_SUMMARY.md`, grade B): FD1 allocates → a FD2 cross-FD mmap can read FD1's data; after free the stale mapping remains valid (UAF); three-way sharing holds.
- **Cannot reach the slab directly**: GPU buffers go through IOMMU/SMMU DMA pages, a **different allocation path** from the kernel slab (kmalloc), with no overlap.
- **Independent corroboration** (grade A): dmesg `arm-smmu 3da0000.kgsl-smmu`, `kgsl-iommu ... Adding to iommu group`.
- **Verdict**: ✅ true.
