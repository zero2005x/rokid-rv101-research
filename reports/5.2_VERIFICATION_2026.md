## 2. 逐列驗證

### 2.1 CVE-2026-21385 — KGSL align sign-extension →「userland 無法控制 align」 ✅ 真

- **漏洞存在性**（`REVERSE_ANALYSIS_1.22_009.md` §9，B 級）：反組譯 `kgsl_iommu_get_gpuaddr`（0xa6170）內 `ubfx x11,x8,#0x10,#0x10; lsl w11,w12,w11` 為 `1 << align` inline、**無 capping、無 `bl kgsl_get_align`** → iommu 路徑為修補前狀態（對應 CodeLinaro commit `91a0db3aa438...`）。
- **不可利用性**（§9.3 實測表）：`GPUOBJ_IMPORT` 雖可設 align 0-255，但 `kgsl_ioctl_gpuobj_import` 內依 size **強制覆寫 align**（≥1MB→20、≥64K→16）；`GPUOBJ_ALLOC` 未註冊（EINVAL）；`GPUMEM_ALLOC` 回 ENOTSUP；`SPARSE_BIND` 無 align 注入。
- **判定**：表列原因「userland 無法控制 align（ioctl 被封閉）」與證據一致。✅

### 2.2 CVE-2026-KGSL-UAF — KGSL syncsource →「SYNCSOURCE ioctl 返回 ENOTTY」 ✅ 真

- **符號存在但未註冊**（A 級）：`msm_kgsl.ko` 含 `kgsl_ioctl_syncsource_create`、`kgsl_ioctl_syncsource_create_fence` 符號，但 dispatch 表未註冊。
- **實測回傳**（`REVERSE_ANALYSIS_1.22_009.md` §9.1，B 級）：`0xc0300930`(SYNCSOURCE_CREATE) → **ENOTTY(25)**；`0xc0180932`(SYNCSOURCE_CREATE_FENCE) → **ENOTTY(25)**。
- **判定**：✅ 真。

### 2.3 CVE-2024-36971 — 路由表 (dst) UAF →「v1-v13，loopback DST 永不 obsolete」 ✅ 真（環境性）

- **版本未修補**（`CVE-2024-36971_analysis.md`，B 級 + 公開 C 級）：影響 5.5–5.10.218，修復 5.10.219；本設備 5.10.209 < 5.10.219、安全補丁 2024-07-05 < 2024-08-05 → **理論上未修補**。
- **不可觸發**（`FINAL_STATUS_20260202.md` 表 + `CVE-2024-36971_analysis.md` §PoC 測試結果）：v1–v13 多策略 PoC（BPF spray 16,384 個 192-byte 物件成功）長時間跑不出 UAF；設備無外部網路、無法產生 ICMP unreachable 觸發 `__dst_negative_advice()`；loopback DST 不會 obsolete。
- **判定**：✅ 真，但屬「本環境不可觸發」，非「已修補」（表標題「已驗證但不可利用」用詞正確）。現存檔 `cve_2024_36971_v13.c`、`cve_2024_36971_bpf_spray.c`、`cve_2024_36971_cross_cache.c`、`cve_2024_36971_wifi.c` 佐證多版本嘗試。

### 2.4 CVE-2024-0582 — io_uring PBUF_RING UAF →「PBUF_RING 功能不存在（需 5.19+）」 ✅ 真

- **功能引入版本**（C 級）：io_uring「ring-mapped supplied buffers」（`IORING_REGISTER_PBUF_RING`）由 commit `c7fb19428d67`（`io_uring: add support for ring mapped supplied buffers`，`for-5.19/io_uring` 分支）引入 → **5.19 起才有**。
- **本設備**：5.10.209 < 5.19 → PBUF_RING opcode/feature 不存在。`CONFIG_IO_URING=y`（io_uring 本身有），但**不含** PBUF_RING 功能。
- **⚠️ 內部不一致提示**：`CVE_PROBE_REPORT_20260203.md` §二 寫「CVE-2024-0582 | CONFIG_IO_URING is not set」，與實際 config（`CONFIG_IO_URING=y`）**矛盾**；`FINAL_STATUS`/`NEW_CVE_ANALYSIS` 及本次萃取皆為 `=y`。**5.2 表的判定（PBUF_RING 不存在）才是正確表述**，該探測報告該列為筆誤。
- **判定**：✅ 真（理由成立）。

### 2.5 CVE-2024-38401 — KGSL UAF →「已修補」 ✅ 真（有依據）

- **修補時點**（C 級）：Qualcomm KGSL syncsource UAF，2024 年 6 月 Android/Qualcomm 安全公告修補；本設備補丁 2024-07-05 → 覆蓋。
- **實測**（`CVE-2024-38401_Test_Report.md`，B 級）：v3–v6（BPF spray 50k–100k 次、多線程 race）**無崩潰**；double-destroy 正確回 EINVAL（`CVE-2025-21479_Analysis_Report.md` §向量 B）。
- **判定**：✅ 真。嚴格說「已修補」是由補丁時點 + 無觸發共同支撐（非單純反組譯確認）。

### 2.6 CVE-2025-21479 / 21480 — KGSL UAF →「Context 創建被阻止」 ✅ 真

- **機制**（`CVE-2025-21479_Analysis_Report.md`，B 級）：Adreno 621 走 A6XX GMU + **hwsched**；`kgsl kgsl-3d0: legacy context switch not supported`；31 種 context flag 組合全部 EINVAL。
- **獨立佐證**（A 級）：`msm_kgsl.ko` 含大量 `a6xx_hwsched_*` 符號（`a6xx_hwsched_boot`、`a6xx_hwsched_context_detach`、`a6xx_hwsched_hfi_*`…），證實 hwsched 硬體排程器模式。
- **判定**：✅ 真。

### 2.7 CVE-2024-43047 / 49848 — FastRPC UAF（ITW, NoviSpy）→「需經 HWBinder 取得 fd，shell 無權限」 ✅ 真

- **驅動存在**（A 級）：`CONFIG_MSM_ADSPRPC=m`（`/dev/adsprpc-smd`）。
- **權限面**（`NEW_CVE_ANALYSIS_20260202.md` §4 + `CVE_PROBE_REPORT_20260203.md` §2，B 級）：節點 `crw-rw-r-- (664) system:system`；shell (uid=2000) groups 不含 `system`，直接 open 失敗；僅 O_RDONLY 若干 ioctl 可用，O_RDWR 需權限。
- **觸發前置**：需透過 `vendor.qti.hardware.dsp@1.0::IDspService`（dspservice, hwbinder）取得 fd；shell 無此 HAL 介面權限。
- **判定**：✅ 真。

### 2.8 CVE-2023-2163 — BPF verifier →「已修補」 ✅ 真

### 2.11 CVE-2021-22555 — Netfilter x_tables →「需 CAP_NET_ADMIN」 ✅ 真（且更強）

- **觸發路徑**（C 級）：Google 官方 writeup「Turning \x00\x00 into 10000$」— 利用需 `setsockopt(IPT_SO_SET_REPLACE)`，需 **CAP_NET_ADMIN**（或靠 user namespace 取得）。
- **本設備阻斷**（A 級）：`CONFIG_NETFILTER_XTABLES=y`（x_tables 存在），但 **`CONFIG_USER_NS is not set`**、**`CONFIG_SYSVIPC is not set`**（斷絕 user-ns 提 CAP 與 msg_msg spray 兩條路）；shell 無 CAP_NET_ADMIN。
- **判定**：✅ 真；「需 CAP_NET_ADMIN」為最直接理由，另有 user-ns/sysvipc 未開的額外阻斷。

### 2.15 KGSL Cross-FD 訪問 — GPU 記憶體隔離繞過 →「資訊洩漏/記憶體損壞，但無法直達 kernel slab」 ✅ 真

- **Cross-FD 成立**（`CVE_2025_21479_EXPLOIT_SUMMARY.md`，B 級）：FD1 配置 → FD2 cross-FD mmap 可讀 FD1 資料；free 後 stale mapping 仍有效（UAF）；三向共享成立。
- **無法直達 slab**：GPU buffer 走 IOMMU/SMMU DMA page，與 kernel slab（kmalloc）**不同配置路徑**，無 overlap。
- **獨立佐證**（A 級）：dmesg `arm-smmu 3da0000.kgsl-smmu`、`kgsl-iommu ... Adding to iommu group`。
- **判定**：✅ 真。
